# OBSプラグイン更新（テスト実装）

このフォルダの実装はSF6 TrackerとWASURENE. Input Displayで共通です。Windows版のみです。

## 動作

- OBSの読み込み完了後、バックグラウンドで各公式GitHubリポジトリの最新安定版を確認します。最新版ならダイアログを出しません。オフライン・取得失敗時は既存版のまま使えます。
- 新版があれば「更新する／あとで」を表示します。更新する場合は公式ZIPのサイズとSHA-256を照合して準備します。
- 「再起動して更新／あとで」で再度確認します。配信・録画・リプレイバッファ・仮想カメラが動いている場合は保留します。
- 補助EXEがOBSの終了を待ち、専用DLLとデータを更新します。OBSを自動で起動し直します。ポータブル起動は引き継ぎます。配信・録画を自動開始する引数は引き継ぎません。
- 更新先は現在読み込まれている通常版／ProgramData版の配置です。設定・対戦履歴のフォルダには触れません。書き込み権限がなければ、OBSを管理者として起動して再度確認してください。更新用EXE自体は昇格を要求しません。
- 更新専用EXEはOBS終了後の入れ替え時だけ動作します。常駐アプリではありません。

## テスト

`WASURENE_UPDATER_TESTING=ON` のビルドには、OBSの「ツール」に「更新テスト（実ファイル変更なし）」が追加されます。「更新する／あとで」の表示だけを試せます。実際の更新・OBS終了は行いません。通常の更新確認は最新安定版を対象とし、テスト版を自動で配布しません。

独立テストはWindowsで実行します。

```
cmake -S updater/tests -B build-updater
cmake --build build-updater --config Release --parallel
python updater/tests/test_updater.py build-updater/Release/updater-check.exe build-updater/updater/Release/wasurene-update.exe
```

テスト用の仮フォルダで、両プラグイン・両配置、設定保持、部分失敗のロールバック、危険なZIP、SHA-256、補助プロセスの終了待ち、別プロセスによるDLLロックを確認します。実際のOBSインストール先は変更しません。

## 失敗・復旧

更新ファイルとバックアップは各プラグインの設定フォルダ内 `updates/<ID>/` に残します。`result.json` で結果を確認できます。通常の書き込み失敗は書き込み済みファイルを戻します。巻き戻しにも失敗した場合や電源断の場合は、OBSを閉じたまま `backup/manifest.json` にある更新先と番号付きバックアップ、または公式ZIPから復旧してください。調査時は `plan.json`・展開済み `payload` も保持してください。

ZIPのSHA-256はGitHubが公開する配布物のハッシュで検証します。独立したコード署名や別経路の署名に代わるものではありません。リポジトリ／配布アカウント自体の侵害への対策は別途必要です。

miniz 3.1.2: https://github.com/richgel999/miniz/tree/3.1.2 。ライセンスと取得元・ファイルハッシュは `vendor/miniz/` に同梱しています。
